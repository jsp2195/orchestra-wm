# Fixed Phase-1 smoke protocol

Smoke is an integration-scale test, not a statistically conclusive experiment. One model initialization (17) is trained on 64 episodes, with the final 8 episodes held out for validation. Evaluation uses three unseen simulator seeds (17, 29, 43 with disjoint experiment offsets), paired across controllers/models. Standard deviation and standard error summarize scenario-seed variation, **not** training-seed uncertainty. No thresholds or objectives are changed in response to evaluation results.

- Primary multi-step comparison: position error in metres at horizon 10, with complete curves at 1, 2, 5, 10, 20, 40. Speed is m/s. Mask error by true active entities. No matching to privileged simulator state is used at model inference.
- Lane occupancy and queue targets are counts divided by 10; both are explicitly supervised. Collision/conflict heads predict pair count per configured vehicle, not calibrated probabilities. Agent-state training targets are simulator labels, never primary-model inputs.
- Action sensitivity: matched current states and targets, correct, shuffled, zero and negated joint action sequences. Positive action gap means shuffled error minus correct error. Time/entity shuffling operates only over controllable entities. Report per scenario and horizon without selecting favorable cases.
- Joint interaction: 2 perpendicular AVs, all four yield/proceed combinations, 12 steps. Both trajectory error and the nonlinear cost contrast C++ - C+- - C-+ + C-- are reported. A smaller contrast error is the direct test of non-additive joint effects.
- Memory: one background vehicle visible for 4 observations, forcibly hidden for 8, then reacquired. Evaluate the forecast immediately before reacquisition. Compare intact state, state reset, a separately trained memoryless model and current observation extrapolation. Reappearance error measures a genuinely held-out observation.
- Counterfactual outcome geometry: pairwise Euclidean distances between all-agent final-position vectors. Pearson/Spearman measure agreement of those distances. Constant predictions have undefined correlations, recorded as null/NaN rather than invented zeroes.
- Decision fidelity: 16 candidates per context, including fixed action audit plans, all scored independently by the simulator. Report cost Pearson/Spearman, pairwise rank agreement (ties explicit), top-5% and top-10% overlap using ceiling, selected true rank (1 = best), and nonnegative selected-cost regret. With 16 candidates the overlaps are effectively top-1/top-2.
- MPC: 6-step horizon, 16 candidates, 2 categorical CEM iterations; 16 execution steps in each task, replanning every step. Only the first command is executed. Oracle uses the identical planner budget and true simulator clones. It is a finite-budget reference, not a proven global ceiling. Learned planning receives no simulator object.
- Objective per transition: delay + 0.5 queue - 0.8 progress + 12 collision + 2 conflict + 0.04 normalized squared acceleration. Components are normalized per configured vehicle. Completion/throughput is separately recorded; short smoke episodes may have zero departures.
- OOD and sensing: same checkpoint, scenario seeds and candidate action plans. Report each perturbation separately. Short 8-step planning checks are diagnostics; they are not pooled with core task results. Source withholding retains public lane geometry. No uncertainty/calibration claim is made.
- Scaling: 4, 8, 16, 24 and 32 agents; forecast error, single-call inference and planner wall latency, selected-plan true cost. Timings include Python overhead and are hardware-specific.

Acceptance status uses transparent descriptive comparisons: lower mean errors/costs and positive correlations support only a PARTIAL scientific claim at smoke scale. A failed direction is NOT SUPPORTED. Architecture-only properties (autonomous API) require passing tests; they do not establish prediction quality. Active sensing and uncertainty are deferred until deterministic planning is useful.

Plot error bars summarize variation across the displayed scenario-seed contexts. Primary seed-summary CSVs first average paired scenarios within each seed, then compute mean, SD and SE across the three seed groups. Use those tables for seed-level comparisons.
